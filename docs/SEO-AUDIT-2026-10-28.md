## Content priorities after this release

1. Expand the passage library: currently only two long passages per fun category; long sessions repeat a complete passage. Add original longer stories and fact-check factual passages. This is a usability limitation rather than a metadata problem.
2. Improve useful, distinct content on the main test pages based on actual queries and user questions. Avoid producing many near-identical keyword pages. The existing metadata is already unique; titles alone are not the main opportunity.
3. Support empirical speed benchmarks with dated primary sources and explain device, population and test conditions. Do not invent universal employer requirements or independent testing claims.
4. Add original screenshots or result examples where they explain a tool. Two editorial images are reused across multiple articles; asset presence does not mean every page has a distinct useful illustration.
5. Use Search Console to establish indexed URLs, query impressions/clicks, canonical selection and mobile performance before claiming ranking improvement. Repository checks cannot establish what Google or AI systems have indexed.
6. Measure real performance before splitting the large legacy src/App.tsx. Preserve route ownership and scoring behavior. React 18 emits a Next.js deprecation notice; plan a separately tested upgrade.
